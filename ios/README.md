# EloraNotes for iPhone

A SwiftUI app on top of the same Rust code the desktop app and the server use. The notes format,
links, search and the shared-library client are not written twice: `core/` wraps them for Swift.

It has **no AI features**: no MCP setup, no memory skill, no assistant marks. The phone app reads
and writes notes, follows `[[links]]`, shows backlinks, searches, and connects to a shared
library.

```
ios/
  core/      the Rust crate the app links (tests run on any computer: cargo test)
  App/       the SwiftUI screens
  scripts/   build-core.sh builds the core for the phone and writes the Swift interface
  project.yml  the Xcode project, generated by XcodeGen, so it is never kept in the repository
```

## What it does now

- Notes on the phone live in the `EloraNotes` folder of the Files app.
- Connect to your shared library (Settings → address, password, name, identifier). The first time,
  the server's certificate code is shown to confirm, as on the desktop.
- Browse, search, read (Markdown with tappable links and backlinks) and edit; edits save by
  themselves.
- Pinned and shared notes are marked; swipe a note to move it to the trash.
- **The graph**, laid out by the same Rust code the desktop app uses: linked notes gather into
  coloured clusters and the notes nothing links to sit on an arc below. Pinch to zoom, drag to move,
  tap a note to light it and its links, then open it. The links inside shared notes are read from
  the server (and kept, so the next graph is quick).

Not yet: pictures in notes, tags and folders as screens of their own, and live co-editing (a
shared note is saved as a whole when you stop typing).

## Looking at it before you set up TestFlight

- **Screenshots.** Every run of the **iOS** workflow starts the app in an iPhone simulator on the
  Mac runner, with made-up notes (the `-EloraDemo YES` launch argument), and takes a picture of
  the list, a note, the graph, search and Settings. Open the run on GitHub → Actions → **iOS** →
  the run → **Artifacts** → `iphone-screenshots`.
- **On your own phone,** where you can touch it: TestFlight, below. It is the only way that
  needs nothing but the Apple account you already have.
- **In a browser,** if you want to click through the simulator without a phone: a service such as
  Appetize.io can run a simulator build. It needs an account of its own and the `.app` from the
  workflow; it is not set up here.

## Building

On GitHub, the **iOS** workflow builds it on a Mac for every change under `ios/`. That is also how
this is built without a Mac of your own. On a Mac:

```sh
ios/scripts/build-core.sh          # Rust core + Swift interface + XCFramework
brew install xcodegen
cd ios && MARKETING_VERSION=$(cat VERSION) BUILD_NUMBER=1 APPLE_TEAM_ID= xcodegen generate
open EloraNotes.xcodeproj
```

## Getting it on your phone with TestFlight

One-time setup on Apple's side:

1. **Register the app.** developer.apple.com → Certificates, Identifiers & Profiles → Identifiers →
   **+** → App IDs → App → Bundle ID **Explicit**: `io.github.noxilith.EloraNotes`.
2. **Make the app record.** appstoreconnect.apple.com → Apps → **+** → New App → iOS, pick the same
   bundle ID, any SKU. (The name has to be unique across the App Store; add a suffix if it is
   taken, it can differ from the name on the home screen.)
3. **Make an API key.** App Store Connect → Users and Access → Integrations → App Store Connect
   API → Team Keys → **+**, access **Admin** (the key lets the build create the signing
   certificate itself, and that needs Admin). Download the `.p8` file (Apple shows it once) and
   note the **Key ID** and the **Issuer ID** at the top of the page.
4. **Add four secrets** to the GitHub repository (Settings → Secrets and variables → Actions):

   | Secret | Value |
   | --- | --- |
   | `APPLE_TEAM_ID` | the 10-character Team ID, under Membership details |
   | `ASC_KEY_ID` | the Key ID |
   | `ASC_ISSUER_ID` | the Issuer ID |
   | `ASC_KEY_P8` | the whole text of the `.p8` file, including the BEGIN and END lines |

Then each time you want a build on your phone: GitHub → Actions → **iOS** → **Run workflow** →
tick **Sign it and upload it to TestFlight**. The build shows up in TestFlight after Apple has
processed it (usually 10–30 minutes). Install the **TestFlight** app on your iPhone, sign in with
the same Apple ID (add yourself under TestFlight → Internal Testing), and install from there. Turn
on Developer Mode if the phone asks (Settings → Privacy & Security).

Signing is automatic: the build asks Apple, through the API key, for the certificate and profile
it needs. Nothing signed is kept in the repository.
